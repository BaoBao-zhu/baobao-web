模型不是全部 工具调用 工作流 常见坑

1. 模型能力只是起点

真正让 Agent 稳定工作的往往不是更强模型本身，而是上下文组织、任务切分和失败恢复策略。

2. 工具调用要显式建模

把可用工具看成接口能力集合，包括输入格式、失败模式、是否阻塞主流程，而不是把所有事情都留给模型自由发挥。

3. 工作流比单次回答更重要

多步任务建议拆成：理解目标、取上下文、执行动作、验证结果、再修正。很多时候这比一条长 prompt 更稳。

一个常见流程：
plan -> inspect -> act -> verify -> summarize

如果任务复杂，再加:
branch -> parallel -> integrate

4. 常见坑

  • 工具太多但没有使用边界
  • 缺少验证步骤，导致输出看起来对但实际不可用
  • 上下文堆得太满，真正关键约束反而被淹没

1. 数据流先理顺

weight stationary、output stationary、row stationary 很容易背混，最好的方式是自己画数据在 PE 阵列和片上 buffer 之间怎么流动。

最值得先比较的点

激活、权重和部分和分别固定在哪一层；谁在移动；重用到底发生在 PE、阵列还是 buffer。

常见阅读误区

只看论文图里的 dataflow 名称，不去追问具体 loop nest、tile shape 和 memory traffic。

2. 存储层次决定代价

很多优化最后都落到“减少更高层级存储访问次数”。可以把每层 buffer 的容量、带宽和重用关系做成表格。

看存储层次时常问：
- 哪一层最容易成为带宽瓶颈？
- 片上 buffer 是否足够撑住 tile？
- 数据重用是否真的发生，还是只是理论上存在？

3. 编译映射别只停在概念

把 tiling、loop ordering、operator fusion、layout transform 放到一个统一框架下，会更容易看到设计空间。

看 NPU 论文时可优先问：
- 它优化的是 compute、data movement 还是 mapping？
- bottleneck 在 on-chip 还是 off-chip？
- 编译器是否参与了调度或 layout 决策？
  • 如果硬件非常灵活，那编译器复杂度通常会上升。
  • 如果映射策略写死，软件栈简单，但泛化能力可能变弱。
  • layout 变换很多时候不是附属细节，而是决定效率的主因之一。

4. 评价一个 NPU 方案时看什么

不要只看 TOPS 或吞吐，至少还要一起看数据搬运代价、利用率、面积约束、灵活性和软件栈成熟度。

架构侧

PE 阵列形状、buffer 组织、互连方式、稀疏支持、调度灵活性。

系统侧

是否容易接入真实模型、编译器是否可用、性能是否能在端到端场景里兑现。

5. 推荐长期维护的问题列表

  • 稀疏性发生在模型、算子还是运行时输入？
  • 性能瓶颈更像带宽受限还是利用率受限？
  • 编译器和硬件接口暴露到了什么粒度？
  • 这个方案如果换一个模型族，收益还成立吗？
